# 产品需求

> 内容取自 PRD(`docs/PRD-ExpenseGuard-MVP.md`)。这是 agent 的速查版 —— 保持简短、保持最新。

## 产品概要
- **产品:** ExpenseGuard
- **一句话:** 面向内部财务团队的费用报销预审系统 —— 把数百至数千行报销数据收敛成需要人看的少数几十行,每条判定附制度条款逐字引用与原始数据行证据链。
- **目标用户:** 企业财务审核员(主);规则配置员 / 管理员、财务负责人(只读)为次。

## 用户故事
- 作为**财务审核员**,我想要**上传本月报销 Excel 并在十几分钟内拿到一份按风险分级、每条判定都附制度条款引用的报告**,以便**把有限人工精力集中在真正高风险的单据上**。
- 作为**财务审核员**,我想要**系统按费用发生日自动匹配当时生效的制度版本**,以便**2 月的费用不会被 5 月的新制度误判**。
- 作为**财务审核员**,我想要**看到跨行关联异常(拆单 / 连号 / 重复 / 时空冲突)及其证据链**,以便**发现单行审核看不出来的问题**。
- 作为**财务审核员**,我想要**在复核台标记「确认违规 / 误报」**,以便**我的判断被记录并用于后续质量评估**。
- 作为**规则配置员**,我想要**以配置而非改代码的方式调整限额阈值与白名单**,以便**制度变更时无需研发介入**。
- 作为**财务负责人**,我想要**每条 AI 判定都能追溯到条款原文与原始数据行**,以便**审核结论经得起内审质询**。

## 功能列表(MoSCoW)

### 必须有(P0 —— 串行依赖 F1→F2→F3→F4→F5)
- [ ] **F1 · Excel 导入与文件版本管理** —— .xlsx 500–5000 行;内容哈希生成 file_version_id;同文件重复导入幂等(行级唯一键)
- [ ] **F2 · Schema 映射与结构化解析** —— 列名映射可保存复用;金额 / 日期归一化;解析失败行进错误清单不静默丢弃;字段可用性三级自动探测(available/inferred/missing)
- [ ] **F3 · 确定性校验** —— 限额 / 票种 / 时效 / 抬头 / 发票号查重五类硬规则(JSON Logic 配置化);阈值白名单为配置项;命中记录 rule_id + rule_version;相同输入 + 规则版本 → 相同输出
- [ ] **F4 · 报告生成(含制度条款引用)** —— 按风险分级;每条判定含规则 / 条款 ID + 逐字引用 + 原始行号;制度检索按费用发生日过滤生效版本并标注版本;**LLM 引用须通过机械式逐字校验方可呈现**;报告可导出
- [ ] **F5 · 人工复核台** —— 按风险排序队列;同屏原始行 + 判定理由 + 条款引用;标记 confirmed/false_positive 带复核人与时间戳写审计日志;**触发被放行样本随机抽检**

### 应该有(P1)
- [ ] **F6 · 跨行关联检测(统计层)** —— 拆单 / 连号 / 频次异常 / 时空冲突;能力声明机制统一挂载;输出全部参与行号 + 证据链
- [ ] **F7 · 异常取证 Agent(ReAct)** —— 只读工具集;最大步数上限;每步落 evidence_step;终止给出「证据是否充分」显式判断
- [ ] **F8 · 二维分级** —— severity_impact / severity_confidence 分列;代价敏感阈值参数化

> P1 三项构成「统计挖候选 → LLM 取证定性」两阶段闭环。W2 进度受阻可先交付关联检测统计层,取证 Agent 顺延,报告降级为「标记候选待人工取证」。

### 可以有(P2)
- [ ] 复核结论回流评测集自动化(MVP 可先手工导出)
- [ ] Trace 面板深化(Langfuse / Phoenix)

### 本版不做(超出范围)
- 模型微调与训练;自研向量数据库;发票真伪官方查验接口(仅设计接口,走 mock)
- K8s 编排 / 多副本 / 自动扩缩容 / 服务网格
- 移动端与平板适配(**仅桌面浏览器端**)
- SaaS 商业化能力(自助注册、计费、租户管理后台)—— 多租户仅架构层预留
- 多智能体协作架构;员工提交端界面;等保测评
- 阈值自动抽取(失败模式静默,刻意推迟至 v2)

## 成功指标
- **漏放率对应召回下限 ≥ 95%**(对被放行样本随机抽样人工复核估算)—— 核心
- 误拦率上限 ≤ 20%(复核台标记 false positive 占比)
- 人工复核工作量下降 ≥ 50%(需人工查看行数 / 总行数)
- 每千行处理成本可测算且有归因(trace 按 task 聚合 token / 延迟 / 成本)
- 激活:完成 ≥1 个真实月度批次全链路;留存:团队连续 2 个月使用

> ⚠ 95% / 20% / 50% 均为**初始假设阈值**,非行业基准,须用自有复核数据按 Neyman-Pearson / 代价敏感方法重新标定(不按 F1 优化)。**采样偏差警告:** 若只标注被拦截样本,漏放率数学上不可测 —— 从第一个批次起就必须对被放行样本随机抽检。

## 超出范围(构建时须遵守)
- 见上方「本版不做」。构建时即使被要求也不得越出 MVP 范围(尤其:不建员工端界面、不做移动端适配、不做阈值自动抽取自动生效、不做 SaaS 计费 / 注册)。
