# 测试策略

## 框架
- **后端单元 / 集成:** pytest
- **LLM 评测门禁:** DeepEval(CI 中跑 pytest,召回率低于基线阈值即阻断合并)
- **注入红队:** promptfoo(CI 中跑注入向量集合)
- **RAG 指标:** Ragas
- **前端单元:** Vitest
- **端到端:** Playwright

## 测试优先级(团队已确认,资源不足时自上而下保)
| 优先级 | 测试对象 | 形式 | 为何最高 |
|---|---|---|---|
| **1** | **幂等性与中断恢复** | 集成测试:处理中途 kill,重启后校验无重复副作用 | LangGraph 节点重放是已知结构性风险,出错后数据污染难察觉 |
| **2** | **规则引擎判定正确性** | 单元测试 + 决策表用例 | 承担约 60% 判定量,错误影响面最大 |
| **3** | **引用校验有效性** | 构造幻觉引用,验证能被拦截 | 证据链可信度最后防线 |
| 4 | 关联检测算法 | 合成数据构造已知异常,验证召回 | 合成数据生成器在此复用 |
| 5 | API 与前端 E2E | 主流程 happy path | —— |

## 规则与要求
- **覆盖率:** 核心模块单元测试 80%;关键路径必须有集成测试。
- **提交前:** 跑 `pytest`(后端)/ `npm run test`(前端);pre-commit 钩子(format / lint / secret 扫描)必过。
- **失败处理:** 未经人类批准,绝不跳过测试或 mock 掉断言来让流水线通过。若 Agent 弄坏了测试,Agent 必须修好。

## 采样抽检机制(不可省略)
- **若只标注被拦截样本,漏放率在数学上不可测量**(reject inference / selection bias)。
- 每批次处理完成后,从**被放行行**随机抽样写入 `sampling_audit`;抽检结论与复核结论合并,才能给出带置信区间的漏放率估计。
- 该机制在**第一个批次即上线**,不是后续优化项。

## 阈值标定方法
- 不按 F1 优化。采用固定可接受误拦率上限、在该约束下最小化漏放(Neyman-Pearson),或代价敏感 `C(τ) = c_FP·FP(τ) + c_FN·FN(τ)` 在验证集选阈值。
- PRD 中 95% / 20% 为初始假设,必须用自有复核数据重新标定。

## 合成数据陷阱须防
- 分布偏离真实、模式过于规整导致「背题」、标签泄漏。缓解:用真实批次校验生成器的分布假设,生成时引入噪声与边界样本。合成数据生成器(`backend/synth/`)覆盖各类违规模式(超限额 / 错票种 / 超时效 / 抬头错 / 连号 / 拆单 / 重复 / 时空冲突),正负样本齐备。

## 执行
- 运行全部后端测试:`pytest`
- 运行单个测试文件:`pytest path/to/test_file.py`
- 前端测试:`npm run test`
- 前端单文件:`npm run test -- path/to/file.test.ts`
